Interne GNSS-Störung 82: Fehler am GNSS-Empfänger — was tun

Truck Data TechnologyAktualisiert September 20263 Min. Lesezeit

Code 82 bedeutet: Der Tachograph hat einen internen Fehler am GNSS-Empfänger festgestellt — nicht nur einen vorübergehenden Signalverlust. Laut Handbuch kommen dafür ein interner Gerätefehler, ein Kurzschluss der externen GNSS-Antenne oder eine fehlende Verbindung zur externen Antenne infrage. Bestätigen Sie die Meldung; bei wiederholtem Auftreten ist eine autorisierte Fachwerkstatt gefragt.

Schweregrad
Mittel

Werkstattkonsultation nötig, keine sofortige Fahrtunterbrechung.

Betroffenes Bauteil
GNSS-Empfänger / Antenne

Interner Gerätefehler oder Antennenproblem, kein reiner Empfangsausfall.

VDO Anzeige
082

EventFaultType 0x36 nach Anhang I C — wird im Massenspeicher erfasst.

Was es bedeutet

Was dieser Code bedeutet

Intelligente Tachographen verfügen über einen eingebauten GNSS-Empfänger, der die Position des Fahrzeugs bei Schichtbeginn, Schichtende und in regelmäßigen Abständen während der Fahrt aufzeichnet. Code 82, interne GNSS-Störung, bedeutet laut VDO-Handbuch einen „Fehler am GNSS-Gerät: interner Fehler, Kurzschluss der externen GNSS-Antenne (Option) oder keine Verbindung zur externen Antenne“.

Nicht mit Code 83 verwechseln

Code 82 bedeutet, dass der Empfänger selbst oder seine Antenne defekt ist — ein Hardwarefehler. Code 83, fehlende Positionsdaten des GNSS-Empfängers, bedeutet dagegen, dass der Empfänger funktioniert, aber innerhalb von drei Stunden kumulierter Lenkzeit kein gültiges Positionssignal empfangen hat.

Was jetzt zu tun ist

Was jetzt zu tun ist

  1. Meldung am Display bestätigen.
  2. Autorisierte Fachwerkstatt konsultieren.
  3. Bei einem Stoneridge SE5000: Die Werkstattprozedur für DTC 000C31 ist Aus- und Wiedereinschalten des Tachographen und eine Probefahrt; bleibt die Störung bestehen, muss der Empfänger ersetzt werden.
  4. Tagesausdruck erstellen und die Zeit bis zur Reparatur handschriftlich dokumentieren.

Was Sie nicht tun sollten

Was Sie nicht tun sollten

  • Nicht davon ausgehen, dass es sich nur um einen vorübergehenden Empfangsausfall handelt — es ist ein Gerätefehler.
  • Den Werkstattbesuch nicht unbegrenzt aufschieben — betroffen ist das Positionsmodul der Aufzeichnung.
  • Nicht selbst an GNSS-Antenne oder Verkabelung hantieren.
  • Nicht mit Code 83 (fehlende Positionsdaten) oder Code 96 (GNSS-Anomalie) verwechseln.
Warum es passiert

Warum es passiert

Laut Handbuch hat Code 82 drei mögliche Ursachen:

  • ein interner Fehler des GNSS-Geräts selbst;
  • ein Kurzschluss der externen GNSS-Antenne, falls eine verbaut ist; oder
  • eine fehlende Verbindung zur externen GNSS-Antenne.

Auf dem Stoneridge SE5000-8.1 wird derselbe Zustand als DTC 000C31 geführt: „Der interne GNSS-Empfänger liefert keine Positionsdaten mehr.“

Nicht zu verwechseln mit GNSS-Störsendern: Störungen des GNSS-Signals durch Jamming oder Spoofing, über die vor allem im Ostseeraum berichtet wird, betreffen den Empfang von außen, nicht das Gerät selbst. Das Handbuch führt sie unter eigenen Codes — fehlende Positionsdaten (Code 83) und GNSS-Anomalie (Code 96). Code 82 ist ein interner Gerätefehler und erfordert unabhängig davon eine Werkstattkontrolle.

Dürfen Sie weiterfahren?

Dürfen Sie weiterfahren?

Ja, grundsätzlich schon. Das Handbuch stuft Code 82 als Störung mit mittlerer Priorität ein: Meldung bestätigen und eine autorisierte Fachwerkstatt konsultieren — anders als bei einer Sicherheitsverletzung wird die Karte nicht ausgeworfen und die Aufzeichnung nicht gestoppt. Formal gilt die Reparaturpflicht nach Artikel 37 der Verordnung 165/2014: Werkstattbesuch, sobald die Umstände es zulassen, spätestens innerhalb einer Woche nach Feststellung der Störung. Weil das Positionsmodul der Aufzeichnung betroffen ist, sollten Sie den Termin zügig vereinbaren, statt ihn unbegrenzt hinauszuzögern.

Folgen für das Unternehmen

Folgen für das Unternehmen

Die Störung wird als EventFaultType 0x36 („Interner GNSS-Empfänger“) nach Anhang I C der Verordnung (EU) 2016/799 im Massenspeicher der Fahrzeugeinheit und auf der Fahrerkarte gespeichert und ist bei jeder späteren Auswertung oder Kontrolle sichtbar. Da sie das Positionsmodul der Aufzeichnung betrifft, kann sie bei einer BAG-Kontrolle Rückfragen zu fehlenden oder lückenhaften Positionsdaten auslösen.

Bleibt die Störung unrepariert, drohen bei einer Straßenkontrolle Beanstandungen wegen Verstoßes gegen die Reparaturpflicht nach Artikel 37 — unabhängig von der tatsächlichen Ursache. Ein dokumentierter Werkstattbesuch mit Prüfbericht ist deshalb die wichtigste Absicherung für das Unternehmen.

Fragen & Antworten

Häufig gestellte Fragen

Ist Code 82 dasselbe wie ein fehlendes GNSS-Signal (Code 83)?

Nein. Code 82 bedeutet, dass der GNSS-Empfänger oder seine Antenne defekt sind — ein Hardwarefehler. Code 83 bedeutet, dass der Empfänger funktioniert, aber innerhalb von drei Stunden kumulierter Lenkzeit kein gültiges Positionssignal empfangen hat.

Darf ich mit interner GNSS-Störung 82 weiterfahren?

Ja, grundsätzlich schon — das Handbuch stuft Code 82 als Störung mit mittlerer Priorität ein. Bestätigen Sie die Meldung und konsultieren Sie eine autorisierte Fachwerkstatt; formal gilt die Reparaturpflicht nach Artikel 37, spätestens innerhalb einer Woche.

Was bedeutet DTC 000C31 auf dem Stoneridge SE5000?

DTC 000C31 ist der Werkstattcode des Stoneridge SE5000-8.1 für dieselbe interne GNSS-Störung: Der interne GNSS-Empfänger liefert keine Positionsdaten mehr. Die Werkstattprozedur ist Aus- und Wiedereinschalten des Tachographen und eine Probefahrt; bei wiederkehrender Störung muss der Empfänger ersetzt werden.

Was verursacht eine interne GNSS-Störung am Tachographen?

Laut Handbuch drei mögliche Ursachen: ein interner Fehler des GNSS-Geräts selbst, ein Kurzschluss der externen GNSS-Antenne, falls eine verbaut ist, oder eine fehlende Verbindung zur externen GNSS-Antenne.

Können GNSS-Störsender (Jamming oder Spoofing) Code 82 auslösen?

Nicht direkt. Code 82 ist ein Gerätedefekt, kein Empfangsverlust von außen. Störungen des GNSS-Signals von außen, wie sie vor allem im Ostseeraum gemeldet werden, zeigen sich im Handbuch üblicherweise als Code 83 (fehlende Positionsdaten) oder Code 96 (GNSS-Anomalie), nicht als Code 82.
